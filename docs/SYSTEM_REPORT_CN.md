## 执行摘要

前沿模型正在把原来分散在推理、代码、网页、专业软件、API和桌面操作中的能力汇聚到同一任务循环中。用户越来越可能只表达目的，模型则在“自己完成、写代码、调用正式接口、操作GUI、借用其他计算机能力、购买外部服务或请求人类复核”之间选择路线。

这并不意味着App、API或权限体系消失。相反，软件将更多承担记录、权限、专业执行、审计、数据治理和可重复运行的职责。真正发生变化的是：**App不再天然拥有工作流入口，功能也不再必须与单个App绑定。**

DIKWP MINEX由此提出一种新的计算基础设施：把一项功能表达成带有语义输入、语义输出、质量、权限、耗费、来源、可逆性和执行表面的能力清单；把用户目的表达成带硬约束的意图；把所有可行能力组合成执行路线；先剔除越权与不合格路线，再从Pareto前沿中选择最小可验证执行耗费路线。

系统同时解决五个关键问题：

1. 模型什么时候应当直接完成功能，什么时候应当调用软件；
2. API、代码和GUI之间如何基于真实耗费与可靠性择路；
3. 同一主体多台计算机如何在不移交一般控制权的情况下借用功能；
4. 不同主体如何以付费方式交换能力结果，并使支付与结果收据绑定；
5. 已成功的工具链如何压缩为可复用“能力配方”，减少后续规划耗费而不扩大权限。

MINEX不把“能量最小”简化成CPU电量最小。系统同时保留物理能耗、时间、金钱、人的注意力、数据暴露、碳排、语义损失与失败概率。只有在权限、质量、隐私和可逆性门槛全部满足后，才允许在这些维度之间作公开的决策权衡。

## 1. 背景辨析：模型拆的是接口墙，不是权限墙

用户提供的文章提出三个关键变化：

- Computer Use逐渐从兜底能力转向常规执行表面；
- Agent可以在运行过程中自主选择API、浏览器、Shell、代码或GUI；
- GUI开始成为机器接口，App可能更多退居“记录系统”而不是“导航系统”。

文章同时明确指出，这种变化并没有使模型获得绕过MFA、SSO、操作系统管理员权限或业务规则的能力；它削弱的是厂商对“机器必须从哪个入口进入”的独占，而不是权限本身。文章还保留了一个重要事实边界：作者当时尚未对相关模型能力进行真实独立测试。

OpenAI的官方资料提供了更窄但可核实的支持：GPT-6 Astra被描述为在计算机使用、浏览、软件工程和专业工作方面具有显著提升；官方Computer Use指南把代码执行、结构化computer工具以及已有的function/MCP接口并列为可用路径，并特别建议Astra优先采用代码执行，同时要求集成方在隔离环境中施加权限规则、执行限制和结果检查。

因此，MINEX采取以下基础判断：

\[
GUIAccess\neq Authorization
\]

\[
ModelCapability\neq BusinessAuthority
\]

\[
AppOptionality\neq AppIrrelevance
\]

软件仍然提供高价值资产：数据库、身份、审计、规则、专业算法、可重复执行和合规边界。模型获得的是**择路能力**，而不是自动获得这些资产的合法控制权。

## 2. 从App经济转向能力经济

传统软件结构通常为：

```text
用户知道目标
→ 用户选择App
→ 用户适应该App的界面与流程
→ App定义入口和顺序
→ 结果留在App中
```

模型优先结构逐步变成：

```text
用户声明目的
→ 模型理解语义结果
→ 系统发现可用能力
→ 比较模型、代码、API、GUI、远程节点、市场和人类路径
→ 选择符合权限与质量的低耗费路线
→ 结果回写到适当的记录系统
```

在这种结构中，“功能”不再等于“软件产品”。一个功能可以由多种表面实现：

\[
Capability=
(
InputSemantics,
OutputSemantics,
Quality,
Authority,
Cost,
Surface,
Provenance,
Terms
)
\]

这使能力具有三种新的流动性：

1. **表面流动性**：同一结果可由模型、代码、API或GUI实现；
2. **空间流动性**：能力可以在同一主体的不同设备之间有界借用；
3. **经济流动性**：能力结果可以由不同主体报价、购买和核验。

MINEX不是取消软件，而是将软件从“唯一入口”重构为能力供应者和记录系统。

## 3. DIKWP语义路由

MINEX将任务输入和输出表示成语义类型，例如：

```text
text.raw
text.summary
text.stats
json.normalized
table.profile
report.markdown
artifact.sha256
```

用户意图定义为：

\[
I=(P,X,Y,Q,A,B,W)
\]

其中：

- \(P\)：目的；
- \(X\)：已有输入及语义类型；
- \(Y\)：必须形成的结果类型；
- \(Q\)：最低质量与最大失败风险；
- \(A\)：已授予权限；
- \(B\)：能耗、时间、费用、隐私等预算；
- \(W\)：在有效路线之间使用的偏好权重。

DIKWP在此不是固定D→I→K→W→P流水线，而是能力图中的语义转换：

- 数据可以被标准化为信息；
- 信息可以被核验并形成知识；
- 知识可以结合语境形成智慧；
- 智慧可以形成可执行Purpose；
- 行动结果再回流为数据、信息和知识。

每个能力只声明它真正需要和提供的语义类型。系统因此可以组合路径，而不必先知道某个App的完整工作流。

## 4. 八种能力表面

### 4.1 模型直接能力 `model_native`

适合：

- 解释、综合、草拟和开放性推理；
- 一次性、低副作用结果；
- 工具协调成本高于直接生成成本的任务。

风险：

- 失败概率和语义损失不稳定；
- 可验证性弱；
- 大模型调用可能引入费用、隐私和能耗；
- 不能把流畅结果当成事实证明。

### 4.2 本地代码 `local_code`

适合：

- 确定性转换；
- 批量处理；
- 结构化数据；
- 哈希、格式化、统计和规则检查。

优点是低暴露、可重复、可测试。局限是需要明确输入和算法，不适合所有开放性任务。

### 4.3 本地或正式API `local_api`

API通常具有高速度、稳定性、计量和权限管理优势。MINEX不会因为GUI变得可用就否定API，而是把它作为一条具有已知成本与质量的高速路径。

### 4.4 GUI或Computer Use `local_gui`

适合没有正式机器接口、需要进入专业软件或界面状态本身重要的任务。由于GUI往往包含更多视觉循环、误点击、弹窗、状态漂移和验证步骤，系统将其重试和验证耗费显式加入总成本。

### 4.5 同主体远程节点 `same_owner_peer`

一台设备可以借用另一台设备的受限功能，例如GPU推理、专业软件导出或本地数据处理，但必须使用租约，绑定能力、提供者、消费者、主体域、期限、调用次数和费用上限。

### 4.6 付费能力 `market_service`

第三方供应方可以提供结果能力。MINEX市场首先按输出类型、预算、质量和可用性过滤，再比较价格与预期耗费。参考实现只生成结算提案，不自动付款。

### 4.7 人类能力 `human_delegate`

在伦理判断、关系谈判、法律、医疗、高风险审批和复杂现实语境中，人类能力仍然是合法路径。人的时间和注意力被作为成本记录，但不能因此被自动排除。

### 4.8 已验证配方 `recipe`

已成功完成并形成结果收据的路径，可以压缩成配方能力。配方保存步骤、语义类型、质量、来源和权限边界，以减少下一次规划与协调耗费。

## 5. 最小可验证执行耗费

### 5.1 不把不同单位静默相加

一条路线的耗费向量为：

\[
\mathbf C(\rho)=
(E,T,M,H,X,G,L,P_f)
\]

分别表示：

- \(E\)：预期物理能耗；
- \(T\)：延迟；
- \(M\)：金钱；
- \(H\)：人的注意力；
- \(X\)：数据暴露；
- \(G\)：碳排；
- \(L\)：语义损失；
- \(P_f\)：失败概率。

这些维度不会被假装成天然可交换。系统先以每个维度执行硬约束和Pareto比较；只有在多条路线均有效且互不支配时，才依据使用者公开声明的参考尺度和权重选择一个操作点。

### 5.2 把验证、协调和失败重做计入能耗

原始执行能耗并不足以比较路线。MINEX定义：

\[
E_{exp}
=
E_{exec}
+
E_{verify}
+
E_{coord}
+
\frac{p_f}{1-p_f}E_{retry}
\]

低成本但高失败的GUI路线，可能比一次性较可靠的API或模型路线消耗更多能量和人的注意力。反过来，对简单确定性任务，调用大模型可能远高于一段本地代码。

### 5.3 质量门与路线质量

路线质量使用最弱能力、语义损失和失败风险共同约束：

\[
Q(\rho)
=
\min_j q_j
(1-L_\rho)
(1-0.35P_{f,\rho})
\]

这是透明的工程启发式，不是普遍真理。不同领域应校准自己的质量模型。

### 5.4 Pareto前沿

有效路线集合为：

\[
\mathcal R^*=
\{\rho\mid Authority,Quality,Privacy,Budget,Reversibility\}
\]

Pareto前沿为：

\[
PF=\{\rho\in\mathcal R^*:\nexists\rho'\prec\rho\}
\]

归一化评分只在前沿内进行：

\[
J(\rho)
=
\sum_k w_k
\frac{c_k/r_k}{1+c_k/r_k}
\]

其中 \(r_k\) 是用户声明的参考尺度。

## 6. 能力“内化”的严格定义

模型可以在实践中学会何时使用工具、如何组合工具，甚至生成代码操作GUI。但是在没有训练或参数更新证据时，不能声称API已经被永久“吸收进模型权重”。

MINEX将可验证的内化分为四级：

| 等级 | 含义 |
|---|---|
| I0 | 每次重新规划，没有持续结构 |
| I1 | 保存能力清单和使用说明 |
| I2 | 从结果收据中生成可重放配方 |
| I3 | 通过重复测量校准配方成本和质量 |
| I4 | 经明确训练流程修改模型参数，并单独验证；不由参考内核声称 |

参考实现达到I2。配方压缩为：

\[
K_{recipe}
=
Compress(Trace,Types,Authority,Receipt)
\]

配方不继承未写入的权限，也不能将闭源程序实现复制为开源代码。

## 7. 多设备能力借用

### 7.1 租约模型

能力租约：

\[
L=(C,P,R,O,T,N,B,S)
\]

其中：

- \(C\)：能力ID；
- \(P\)：提供节点；
- \(R\)：消费节点；
- \(O\)：主体域；
- \(T\)：到期时间；
- \(N\)：调用预算；
- \(B\)：金钱预算；
- \(S\)：签名。

租约不等于远程桌面权限，不等于访问全部文件，也不自动授予网络、支付或外部行动权。

### 7.2 同主体不等于无边界

即使多台计算机属于同一人，也可能处在不同信任区：

- 工作设备；
- 家庭设备；
- 云服务器；
- 含敏感医疗或财务数据的设备；
- 临时租用的算力节点。

因此系统仍需要最小字段、最小权限、期限、调用次数和结果摘要。

### 7.3 后继Agent不得继承权限

用户提供的多Agent背景指出，前代Agent留下的方法和工件可以被后续更强模型利用。因此：

\[
SuccessorAuthority
\not\Leftarrow
PredecessorArtifact
\]

新Agent可以读取被允许的配方，却必须重新获得租约。删除一个运行实例也必须同时检查租约、令牌、缓存、任务队列、共享工件和后继清单。

## 8. 能力交易

付费能力市场中的报价至少包含：

```text
provider_id
capability_id
provides
price and currency
expected energy
quality
availability
owner-realm restrictions
warranty or refund terms
```

市场清算先过滤不满足输出、预算和主体域要求的报价，再按价格、能耗和质量排序。真实结算必须绑定：

```text
winning bid
result receipt digest
verification status
dispute and refund terms
named payer and payee
```

参考内核输出：

```text
PROPOSAL_ONLY_NO_REAL_PAYMENT
```

它没有银行、钱包、税务或合同权限。

长期可以形成一种“能力流动市场”：软件厂商、模型供应商、个人设备、组织节点和人类专家都可以发布能力清单，由Agent按目的和总耗费选择。但这种市场必须避免：

- 隐藏质量排名；
- 将低报价等同于高价值；
- 平台垄断能力入口；
- 秘密出售用户数据；
- 未经授权把任务发给第三方；
- 结果失败却无法退款或纠错。

## 9. 能耗与碳排的证据边界

系统区分三种来源：

```text
measured
provider-reported
declared / modeled
```

只有附带硬件边界、测量方法、功能单位、时间窗口和工具版本的记录，才能称为测量。一个模型服务的“每次调用能耗”如果没有供应商或独立遥测，只能作为声明或估计。

MINEX的碳维度可以与Software Carbon Intensity方法连接：

\[
SCI=(E\times I+M)/R
\]

其中 \(E\) 为能量，\(I\) 为地区电力碳强度，\(M\) 为硬件隐含排放份额，\(R\) 为功能单位。当前参考内核只保存声明的碳值，尚未完整实现SCI核算。

最重要的原则是：

> 没有可靠物理测量时，不用一个精确到小数的数字制造“绿色最优”的假象。

## 11. 可落地场景

### 11.1 个人计算

用户说“整理这份文件并生成简报”，系统可以判断：简单统计和提取式摘要由本地代码完成，开放性润色才调用模型，从而减少不必要的远程调用和隐私暴露。

### 11.2 企业知识工作

同一目的可以连接CRM API、浏览器检索、代码处理和文档系统。MINEX保存权限与结果收据，使Agent不能因为“最终报告需要完成”就静默跨越系统边界。

### 11.3 设计与专业软件

当Blender、CAD、Power BI等缺少合适API时，GUI可以成为备选表面；但如果有稳定脚本或正式接口，系统可能因重试和验证成本更低而优先选择它们。

### 11.4 多设备个人算力

笔记本可以向同一主体的工作站借用GPU推理或视频处理能力，只暴露必要输入，并限定一次调用和十五分钟有效期。

### 11.5 能力市场

小型组织可以购买一次专家校核、专业转换或高质量模型输出，而不必购买完整软件席位。供应者只有在形成验收收据后才能进入结算程序。

### 11.6 软件厂商转型

软件不再只按席位收费，而可以发布可计量能力、质量保障、审计和记录服务。厂商竞争重点从“锁住用户导航入口”转向“让Agent愿意选择正式、低耗、可信接口”。

- 收据；

- API/MCP/GUI连接器；
- 实际能耗测量；
- 能力市场托管；

- 多节点调度；
- 私有部署和SLA；
- 行业策略包；
- 审计和标准符合性服务。

最短商业试点可以选择一个组织内的20—50个重复任务，比较“当前固定App流程”与“MINEX择路”的：


只有在相同功能单位与质量门槛下比较，才能声称节约。

## 13. 标准化：MINEX-1000

MINEX-1000定义六级累积符合性：

| 等级 | 核心要求 |
|---|---|
| L0 | 明确意图、语义输入/输出和来源 |
| L1 | 机器可读能力清单和执行表面 |
| L2 | 权限、质量、隐私、预算与副作用硬门 |
| L3 | Pareto路线、公开偏好和结果收据 |
| L4 | 有界租约、市场提案、配方内化和后继重授权 |
| L5 | 生产级签名、实测能耗、撤销、支付与独立符合性 |

参考实现目标为L4-reference。L5需要外部身份、硬件密钥、现实支付和独立测量，未被伪装成已经完成。

---

## 14. 风险与边界

当前系统不能证明：

- 枚举了所有可行路线；
- 选择了全局最优路线；
- 声明的能耗就是物理实测；
- 模型直接生成比软件更正确；
- 远程节点值得信任；
- 付费供应者会履约；
- GUI自动化在所有界面中稳定；
- 配方在软件更新后仍然有效；
- 收据中的输入证据本身真实。

生产部署必须增加：

```text
硬件或独立密钥
真正的沙箱
网络与数据隔离
最小权限身份
租约撤销
端到端加密
实际能耗与质量测量
支付或托管合作方
法域和合同规则
独立审计
失败恢复和人工升级
```

---

## 15. 结论

模型优先时代的关键软件不应继续把用户锁在一个新的“超级App”中。它应当把目的、能力、权限、耗费和证据公开化，使模型、软件、设备、人和市场成为可比较但不可越权的执行表面。

MINEX的最终命题为：

\[
\boxed{
\begin{aligned}
&IntentFirst\\
+&CapabilityLiquidity\\
+&AuthorityBeforeOptimization\\
+&QualityBeforeCheapness\\
+&ParetoBeforeWeightedScore\\
+&MeasurementBeforeGreenClaims\\
+&ReceiptBeforeSettlement\\
+&ReauthorizationBeforeInheritance\\
+&CorrectionBeforeClosure
\end{aligned}
}
\]

**当模型可以替代一部分App功能时，真正有长期价值的系统不是替用户决定打开哪个App，而是证明：在不扩大权限、不牺牲质量、不隐瞒数据代价的前提下，哪一组能力能够以最小可验证耗费完成用户真正的Purpose。**
