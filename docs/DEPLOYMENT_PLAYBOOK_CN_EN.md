# Deployment Playbook / 部署手册

## Phase 0 — Baseline / 基线

Select 20–50 repeatable tasks. Define the functional unit, acceptance criteria, current workflow, authorities, data classes, and measurement method.

选择20—50个重复任务，固定功能单位、验收条件、现有流程、权限、数据分类和测量方法。

## Phase 1 — Read-only planning / 只读规划

Run MINEX without execution. Compare proposed model, code, API, GUI, peer, and human routes. Review false rejections and unsafe suggestions.

## Phase 2 — Local reversible execution / 本地可逆执行

Enable only registered deterministic local handlers. Require receipts and rollback.

## Phase 3 — Same-owner peer / 同主体节点

Introduce short-lived signed leases, encrypted transport, node allowlists, and revocation. Start with non-sensitive data and one-call budgets.

## Phase 4 — External provider pilot / 外部供应方

Use fixed-price, low-risk capabilities with warranties and acceptance receipts. Keep payment external and human approved.

## Phase 5 — GUI and professional software / GUI与专业软件

Run in isolated desktops. Use temporary credentials, screen-state verification, maximum action counts, and explicit stop conditions.

## Measurement / 测量

Compare against the baseline using:

```text
success rate
quality acceptance
wall-clock time
human attention
model tokens/calls
API and license cost
data egress
physical energy
rework and retries
incident rate
```

Do not claim savings if the functional unit or acceptance threshold changed.
