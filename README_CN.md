# DIKWP MINEX 能力织网操作系统

> **目的优先，App可选；能力可流动，执行先有证据。**

DIKWP MINEX 面向模型优先计算时代，把用户目的转换成机器可检查的语义输入/输出，再在模型直接完成、本地代码、API、GUI、同主体远程节点、付费能力、人类协作和已验证配方之间选择有效路径。

它不是简单寻找“最便宜的工具”，而是先拒绝越权、质量不足、隐私超限、不可逆或预算超限的路径，再形成 Pareto 前沿，并依据用户声明的多维偏好选择**最小可验证执行耗费**路径。

```text
运行模式：
MESH95_INTENT_CAPABILITY_PARETO_MINIMUM_EXPENDITURE_LEASE_RECEIPT_CLOSURE

预标准：
MINEX-1000:2026-DRAFT
Minimum Verified Execution Expenditure Capability Protocol

许可证：Apache-2.0
自动外部行动权限：0
自动付款权限：0
自动签约权限：0
自动远端发布权限：0
```

## 最短使用路径

直接打开：

```text
DIKWP_MINEX_CAPABILITY_FABRIC_OS_v1.0.0.html
```

或运行：

```bash
python DIKWP_MINEX_CAPABILITY_FABRIC_OS_v1.0.0.pyz \
  demo --workspace .minex-demo --reset
```

## 核心链路

```text
目的
→ 语义输入与结果类型
→ 能力发现
→ 权限、质量、隐私和可逆性硬门
→ 路径组合
→ Pareto前沿
→ 最小可验证耗费路径
→ 本地执行或有界提案
→ 结果收据
→ 可选配方内化
```

## 为什么不再以App为中心

模型能力提高后，一部分原本必须进入软件界面完成的工作，可以由模型直接推理、写代码、调用工具或操作GUI完成。软件不会消失，但会更多地承担数据记录、权限、专业执行和审计等功能。MINEX因而把“功能”从“App入口”中抽离出来，统一表达为带输入、输出、质量、成本、权限和来源的能力清单。

## 八种执行表面

| 表面 | 含义 |
|---|---|
| `model_native` | 模型直接形成结果 |
| `local_code` | 本地确定性或受限代码 |
| `local_api` | 正式本地接口 |
| `local_gui` | 浏览器或桌面GUI操作 |
| `same_owner_peer` | 同一主体多台计算机间借用能力 |
| `market_service` | 购买第三方能力结果 |
| `human_delegate` | 具名人类完成或复核 |
| `recipe` | 从已验证路径压缩出的可复用配方 |

## 多维耗费

系统不把不同单位粗暴等同。每条路径保留：

\[
\mathbf C=(E,T,M,H,X,G,L,P_f)
\]

即物理能量、时间、金钱、人的注意力、数据暴露、碳排、语义损失和失败概率。预期能耗还包含验证、协调和失败重做：

\[
E_{exp}=E_{exec}+E_{verify}+E_{coord}+\frac{p_f}{1-p_f}E_{retry}
\]

## 多机能力借用

同主体设备之间使用带签名、期限、调用次数和价格上限的能力租约。租约只允许调用指定能力，不等于取得远程计算机的一般控制权。

## 付费能力交易

市场模块可以寻找满足输出、预算和质量要求的供应方，并生成与结果收据绑定的结算提案；参考内核不会真实付款。

## 能力内化

MINEX所说的“内化”是把已验证的执行链压缩成可复用配方，而不是声称修改模型权重或复制闭源软件：

```text
执行轨迹 + 语义类型 + 权限 + 结果收据
→ 配方能力清单
```

配方可以减少今后的规划与协调耗费，但不能扩大权限。

## 现实边界

当前版本是研究型参考实现，不是通用能耗计量器、支付系统、法律市场、操作系统沙箱或真实桌面自动化产品。所有跨设备、GUI、API和付费执行在投入生产前仍需独立权限、隔离、签名、人工批准和现实结果验证。

### 跨设备节点加固

参考节点进一步执行请求防重放、服务端调用预算、提供者/消费者/主体域绑定、请求大小限制，并禁止远程路径输入。MCP账本工具只验证调用者提供的账本文本，不读取调用者指定的任意本机路径。
